# 🎵 Music Recommender Simulation

## Project Summary

In this project you will build and explain a small music recommender system.

Your goal is to:

- Represent songs and a user "taste profile" as data
- Design a scoring rule that turns that data into recommendations
- Evaluate what your system gets right and wrong
- Reflect on how this mirrors real world AI recommenders

This project builds a small music recommender system that scores songs from a 20-song catalog against a user's taste profile. It uses a weighted formula based on mood, energy, valence, and acousticness to rank songs and return the top 5 recommendations with explanations for each match.

---

## How The System Works

### Song Features Used
Each `Song` has the following attributes used in scoring:
- **mood** — categorical label (e.g. chill, happy, intense)
- **energy** — float 0–1, how intense/active the song feels
- **valence** — float 0–1, how positive/negative the song feels
- **acousticness** — float 0–1, how acoustic vs. electronic the song is

### What UserProfile Stores
- `favorite_mood` — the mood the user wants to match
- `target_energy` — the energy level the user prefers (0-1)
- `target_valence` — the positivity level the user prefers (0-1)
- `likes_acoustic` - boolean, whether the user prefers acoustic sounds

### How a Score is Computed
Each song gets a score between 0 and 1 using a weighted formula:

```
score = 0.35 * mood_match
      + 0.25 * (1 - |song.energy - user.target_energy|)
      + 0.25 * (1 - |song.valence - user.target_valence|)
      + 0.15 * acoustic_score
```

- `mood_match` is 1.0 if the song's mood matches the user's, 0.0 otherwise
- Energy and valence use **continuous proximity** — closer to the user's target = higher score
- `acoustic_score` rewards high acousticness if `likes_acoustic=True`, low if `False`

### How Songs Are Recommended
1. Score every song using the formula above
2. Sort all songs from highest to lowest score
3. Return the top `k` songs (default 5)

## Experiments You Tried

- **Dropped genre from scoring** — genre was replaced entirely by mood as the top-weighted feature (0.35) because mood more directly captures how a song feels. Two songs in the same genre can feel completely different, while mood is more consistent.
- **Added valence as a continuous feature** — instead of only using energy, valence (positivity/negativity) was added at weight 0.25. This helped differentiate songs with similar energy but different emotional tone.
- **Tested a conflicting profile (high energy + chill mood)** — a user with `energy=0.90` and `mood=chill` produced unexpected results: chill songs scored well on mood but poorly on energy, while intense songs scored well on energy but got zero mood points. The mood weight (0.35) ended up dominating, so chill songs still ranked higher.
- **Tested a perfectly balanced profile (all mid values)** — a user with `energy=0.50` and `valence=0.50` with `mood=focused` showed that when no mood match exists in the catalog, the system falls back entirely on energy/valence proximity, producing a flat ranking with scores clustered close together.
- **Tested extreme acoustic ambient profile** — a user preferring very low energy (0.10) and high acousticness surfaced Deep Waters and Soft Signal at the top, confirming the acousticness and energy components work correctly together.

---

## Limitations and Risks

- **Tiny catalog** — only 20 songs, so results repeat and diversity is limited regardless of the user profile
- **Mood is binary** — a mood either matches (1.0) or it doesn't (0.0); there is no partial credit for "close" moods like chill vs. relaxed
- **No listening history** — all preferences must be manually defined; the system cannot learn from what a user actually plays
- **No diversity enforcement** — the top 5 could all be by the same artist if they happen to score highest
- **Fixed weights** — the 0.35/0.25/0.25/0.15 weights were chosen manually and may not reflect every user's actual priorities

## Reflection

Read and complete `model_card.md`:

[**Model Card**](model_card.md)

Building this recommender makes it clear that turning user preferences into predictions requires converting everything into numbers — even something as subjective as "mood" becomes a binary 0 or 1. Every design choice (which features to include, how much to weight each one) directly shapes what gets recommended, which means bias can easily enter through those choices. For example, by dropping genre and prioritizing mood, the system may consistently under-serve users whose taste is genre-driven rather than mood-driven. Real systems like Spotify face the same problem at a much larger scale, where small weight decisions affect millions of users.
